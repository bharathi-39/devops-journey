## 1. The `echo` Command

The `echo` command prints text or variable values to standard output.

```bash
echo "Hello, Linux!"
name="Bharathi"
echo "Hello, $name"
```

Command substitution can be used to include another command's output:

```bash
echo "Today is $(date)"
```

A pipe is not useful with `echo` as the command on the right because `echo` normally prints its arguments instead of reading piped input.

```bash
# This prints only "The day is"
date | echo "The day is"

# Correct approach
echo "The day is $(date)"
```

## 2. Creating and Running a Shell Script

Example script:

```bash
#!/bin/bash

echo "Hello from my shell script"
```

Save it as `sample.sh`, grant execute permission, and run it:

```bash
chmod +x sample.sh
./sample.sh
```

It can also be run explicitly with Bash:

```bash
bash sample.sh
```

> Note: On Ubuntu, `sh` is commonly linked to `dash`. Bash-specific features, such as `{1..100}` brace expansion, should be run with `bash script.sh` or a `#!/bin/bash` shebang.

## 3. Basic Node Health Check Script

```bash
#!/bin/bash

set -e
set -x
set -o pipefail

echo "===== Disk Usage ====="
df -h

echo "===== Memory Usage ====="
free -h

echo "===== CPU and Load ====="
uptime

echo "===== Running Processes ====="
ps -ef
```

### Important options

- `set -e`: exits the script when an unhandled command fails.
- `set -x`: prints each command before executing it. This helps with debugging.
- `set -u`: treats an unset variable as an error.
- `set -o pipefail`: makes a pipeline fail if any command in that pipeline fails.

A commonly used strict-mode combination is:

```bash
set -euo pipefail
```

For troubleshooting, command tracing can also be added:

```bash
set -euxo pipefail
```

## 4. Standard Streams

Linux commands normally work with three standard streams:

| Number | Stream | Meaning |
|---:|---|---|
| `0` | stdin | Standard input received by a command |
| `1` | stdout | Normal output generated by a command |
| `2` | stderr | Error output generated by a command |

Example:

```bash
ps -ef | grep "amazon"
```

Flow:

```text
ps -ef stdout -> pipe -> grep stdin -> grep stdout -> terminal
```

Suppress error output:

```bash
find / -name "sample.txt" 2>/dev/null
```

Redirect normal output to a file:

```bash
df -h > disk_usage.txt
```

Append output to a file:

```bash
date >> activity.log
```

## 5. Process Management

The `ps` command displays running processes.

```bash
ps -ef
```

Filter for a particular process:

```bash
ps -ef | grep "amazon"
```

Avoid matching the `grep` command itself:

```bash
ps -ef | grep "[a]mazon"
```

### Important process fields

- PID: Process ID, the unique identifier of a running process.
- PPID: Parent Process ID, the process that started the current process.

Extract process IDs with AWK:

```bash
ps -ef | grep "[a]mazon" | awk '{print $2}'
```

## 6. The `awk` Command

`awk` processes text line by line and works especially well with columns.

For whitespace-separated input:

```bash
ps -ef | awk '{print $2}'
```

Important fields:

- `$0`: entire line
- `$1`: first column
- `$2`: second column
- `$3`: third column
- `$NF`: last column

Examples:

```bash
# Print user and PID
ps -ef | awk '{print $1, $2}'

# Print filesystem and usage percentage
df -h | awk '{print $1, $5}'

# Print only rows where usage is high, excluding the header
# This removes the % symbol before numeric comparison
df -h | awk 'NR > 1 {gsub(/%/, "", $5); if ($5 >= 80) print $1, $5 "%"}'
```

For `ps -ef`, no custom `-F` separator is normally needed because AWK treats whitespace as the default field separator.

## 7. Checking Logs

Common Linux logs are stored under `/var/log`.

```bash
ls -ltr /var/log
```

Useful commands:

```bash
less /var/log/syslog
tail -n 50 /var/log/syslog
tail -f /var/log/syslog
grep -i "error" /var/log/syslog
```

For systemd services:

```bash
journalctl -u amazon-ssm-agent
journalctl -u amazon-ssm-agent -n 50
journalctl -u amazon-ssm-agent -f
```

Log files are useful for troubleshooting, monitoring, security investigation, and identifying the sequence of events before a failure.

## 8. `curl` and `wget`

### `curl`

`curl` sends requests to URLs and prints the response to standard output by default. It is useful for webpages, APIs, headers, health endpoints, and connectivity testing.

```bash
curl https://www.google.com
curl -I https://www.google.com
curl -s -o /dev/null -w "%{http_code}\n" https://www.google.com
curl http://localhost:8080/health
```

Save a response to a file:

```bash
curl -o response.html https://www.google.com
```

### `wget`

`wget` is commonly used to download content to the server.

```bash
wget https://example.com/file.zip
wget -O custom-name.zip https://example.com/file.zip
wget -c https://example.com/large-file.zip
```

### Key difference

- `curl`: commonly used to send requests and inspect responses.
- `wget`: commonly used to download files.

Access still depends on network connectivity, permissions, authentication, and whether the remote server exposes the resource.

## 9. Finding Files

Find a file from the root directory:

```bash
find / -name "sample.txt" 2>/dev/null
```

Case-insensitive search:

```bash
find / -iname "sample.txt" 2>/dev/null
```

Find all log files:

```bash
find /var/log -type f -name "*.log"
```

Quotes are recommended, especially for wildcard patterns and filenames containing spaces.

## 10. Switching Users

Open a root login shell:

```bash
sudo -i
```

Switch to another user:

```bash
sudo su - username
```

Check the current user:

```bash
whoami
```

Return to the previous user or shell:

```bash
exit
```

`Ctrl+D` can also close the current shell.

## 11. Loops and Conditions

### For loop from 1 to 100 in Bash

```bash
for i in {1..100}; do
    echo "$i"
done
```

Single-line version:

```bash
for i in {1..100}; do echo "$i"; done
```

Portable version using `seq`:

```bash
for i in $(seq 1 100); do echo "$i"; done
```

### Find the greater of two numbers

```bash
#!/bin/bash

read -p "Enter the first number: " a
read -p "Enter the second number: " b

if [ "$a" -gt "$b" ]; then
    echo "$a is greater"
elif [ "$a" -lt "$b" ]; then
    echo "$b is greater"
else
    echo "Both numbers are equal"
fi
```

Useful numeric operators:

- `-gt`: greater than
- `-lt`: less than
- `-ge`: greater than or equal to
- `-le`: less than or equal to
- `-eq`: equal to
- `-ne`: not equal to

## 12. The `kill` Command and Signals

The `kill` command sends a signal to a process. It requires a PID.

```bash
kill PID
```

Common signals:

| Number | Signal | Purpose |
|---:|---|---|
| `1` | SIGHUP | Hangup or request configuration reload, depending on the program |
| `2` | SIGINT | Interrupt, commonly generated by `Ctrl+C` |
| `9` | SIGKILL | Immediately force-stop a process |
| `15` | SIGTERM | Request graceful termination, and the default for `kill` |
| `18` | SIGCONT | Resume a stopped process on many Linux systems |
| `19` | SIGSTOP | Pause a process on many Linux systems |

Examples:

```bash
kill -15 1234
kill -9 1234
kill -1 1234
```

List signals on the current system:

```bash
kill -l
```

Use `SIGTERM` first. Use `SIGKILL` only when the process does not respond because it cannot perform cleanup before termination.

## 13. The `trap` Command

`trap` defines an action that the shell should perform when it receives a specified signal or shell event.

Syntax:

```bash
trap 'command' SIGNAL
```

Catch `Ctrl+C`:

```bash
#!/bin/bash

trap 'echo "Ctrl+C received"; exit 130' SIGINT

while true; do
    echo "Script is running"
    sleep 2
done
```

Clean up a temporary file when the script exits:

```bash
#!/bin/bash

TEMP_FILE=$(mktemp)

cleanup() {
    echo "Cleaning up $TEMP_FILE"
    rm -f "$TEMP_FILE"
}

trap cleanup EXIT

echo "Temporary data" > "$TEMP_FILE"
cat "$TEMP_FILE"
```

Important points:

- `trap ... EXIT` is commonly used for cleanup.
- `trap ... SIGINT` handles `Ctrl+C`.
- `trap ... SIGTERM` can support graceful termination.
- `SIGKILL` and `SIGSTOP` cannot be trapped, blocked, or ignored.
